# RFC 6376 Gap Note

`kuroshio-mta` の DKIM 実装は、RSA と RFC 8463 の Ed25519 鍵を使った受信検証と送信署名を対象にしています。

## 現在カバーしている内容

- `rsa-sha256` による DKIM 署名検証
- `ed25519-sha256` による署名・検証と RFC 8463 Appendix A の公開テストベクトル
- DNS の `k=ed25519; p=...` は raw 32 byte の公開鍵を使用し、署名アルゴリズムと鍵種別の不一致を拒否
- 複数署名の集約評価
- `simple` / `relaxed` canonicalization
- `h`, `bh`, `b`, `l`, `t`, `x` の主要タグ検証
- 送信時の DKIM 署名付与と鍵ローテーション時の再読込
- 署名生成と検証の相互運用テスト
- RSA / Ed25519 の複数署名の評価と、鍵更新時のアルゴリズム切り替え
- 署名ヘッダ自身の末尾 CRLF をハッシュ対象に含めない正規化

## 鍵の選択と移行

`dkim_private_key_file` の鍵種別からアルゴリズムを自動選択します。RSA は PKCS#1 / PKCS#8 PEM、Ed25519 は PKCS#8 PEM を読み込みます。設定手順は [メール認証チュートリアル](./tutorials/mail-auth.md#ed25519-の鍵を使う) を参照してください。

同じ設定・鍵を ARC でも使うため、ARC の AMS / seal も Ed25519 に対応しています。受信側は RSA と Ed25519 が混在した ARC chain を検証できます。

送信設定は1つの鍵・selectorです。RSA と Ed25519 の同時署名を自動追加する設定は提供しません。既存の別 selector の署名は保持します。鍵の種類を変える移行では新しい selector を使い、以前の DNS 公開鍵を検証に必要な期間残してください。

旧実装が余分な末尾 CRLF を含めて生成した署名は、修正後の検証では失敗します。その形式を受理するフォールバックは行いません。

## 実装範囲外として扱う内容

- RSA / Ed25519 以外の公開鍵種別
- DNS 公開鍵ポリシーの細かな運用差異の吸収

## 判断メモ

RSA と Ed25519 の署名・検証を対象とします。外部 MTA との広範な相互運用やすべての公開鍵ポリシーへの対応を保証するものではありません。
